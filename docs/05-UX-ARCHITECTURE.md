# UX Architecture

## Guardrails

- Próxima ação clara.
- Linguagem não técnica.
- Progressive disclosure.
- Mobile validado.
- Estados de loading, vazio, erro e sucesso quando aplicáveis.
- Informação operacional interna não é exposta ao membro.
- A home do membro não deve virar um dashboard corporativo.
- O membro nunca deve precisar descobrir sozinho o próximo passo.
- TutorIA deve estar disponível no contexto da ação, sem obrigar o membro a abandonar missão ou ferramenta.
- Ferramentas devem parecer workspaces conduzidos, não formulários burocráticos ou caixas de texto isoladas.

## Presença do TutorIA

1. **Contextual:** orientação, pergunta ou insight dentro da tela atual.
2. **Painel:** side panel no desktop e drawer no mobile para executar a missão ou ferramenta em conjunto.
3. **Workspace:** ambiente completo para decisões, revisão, exploração e acompanhamento de compromissos.

O botão flutuante e os CTAs “Pedir ajuda ao TutorIA” são entradas complementares. A interface não deve simular capacidades ainda indisponíveis; estados futuros precisam ser identificados com clareza.
